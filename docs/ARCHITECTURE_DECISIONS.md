# 实施决策

## ADR 001：依赖与平台

决策：Rust 1.99.1，edition 2024；默认应用固定 `gpui-kit =0.9.0`，只通过 Kit 导出的 GPUI 类型交互。普通文本共享 `ropey =2.0.0-beta.1`；Cargo.lock 固定传递依赖。NSH 0.4.0 放在独立 `spikes/nsh-eval` workspace，Kit Fast 候选不改变默认应用依赖。

依据：crates.io 实际获取了 Kit 0.9.0、NSH engine/platform 0.4.0。官方 NSH v0.4.0 embed-gpui 示例使用 Kit 0.7.3 + Fast 0.1.9，并未验证本项目的新组合。Kit 0.9.0 的 Fast 特性声明 ^0.1.13；独立候选 lockfile 解析 Fast 0.1.13。解析成功不等于构建或交互通过。

平台：macOS 原生 Apple Silicon Mac16,10 / 32 GiB 为实测机。Parallels Windows 11 guest 报告 ARM64，不作为 Windows x64 原生验收。最低 macOS 版本和 Intel 产物尚未验证。

替代方案：直接把 NSH 加入默认 workspace 会扩大依赖与 feature 统一影响；目前隔离更便于同机测增量成本。未引入第二套 JS 宿主。

实际候选构建发现两项上游不兼容：rolldown 1.2.13 与自动选出的 1.3.0 helper API 不匹配，已锁定同代 helper；原版 NSH platform 0.4.0 使用动态字符串调用 Fast 0.1.13 只接受静态字符串的 `KeyBinding::new`，不能直接编译。经评审仅在独立 spike vendoring NSH platform，改为动态 `KeyBinding::load`，非法快捷键非致命报告，不泄漏字符串。来源与许可证见 `spikes/nsh-eval/vendor/nsh-platform-gpui/PATCHES.md`。带此补丁的 release 混合程序已构建成功；不能描述为“原版组合直接兼容”。

## ADR 002：唯一文本权威与事务

决策：Kit EditorState 为唯一可变普通文本与撤销权威。adapter 只在 InputEditsEvent 完成提交时推进宿主版本，保留不可变 committed Rope 快照，不持久化 IME preedit，不用 set_value 全文同步。

由 design-review 审查的约束：程序化批量 edits 先校验版本、边界、非重叠，再一次原子修改和撤销。若 stock API 无法表达，应最小补丁或有界编辑跨度合并，不能逐条制造多个撤销事务。具体实现通过运行验证前不宣称通过。

脏标记：不能每次键入全文 hash 或全文 Rope 相等比较。长度不同可直接 dirty；长度相同需带文档版本的后台相等比较或可靠历史保存点，迟到结果不得清除新版本的 dirty。

100 标签：启动只载入元数据与活动文档。未激活标签不创建 EditorState；其构造有按键监听与光标实体成本。

程序化编辑的同步返回必须对应提交后的宿主版本和不可变Rope；不能等迟到事件再更新后，立即用旧快照执行替换后的搜索。修订契约经评审：统一提交函数同步推进程序化编辑，原生事件以不可变编辑描述与Rope实例身份匹配确认，避免重复递增/恢复提交。若存在尚未交付的原生编辑，利用固定Ropey版本的 `extra::esoterica::ropes_are_instances` O(1)检查拒绝当前程序化调用，不能用仅长度比较漏掉等长修改。初始化快照必须直接clone实际EditorState文本；不增加第二个可变文本权威。

所有身份编辑与合并后不改变内容的批次必须是NoOp，仍先校验坐标/版本；不制造空撤销、假版本或dirty。事件匹配使用事件自带不可变快照，不比较可能已被下一事务修改的当前文本。

## ADR 003：NSH 候选

决策：暂缓进入主线，独立验证 headless 方法授权、调用、脚本异常、限时循环、停止重开；混合原型另验证 AppView、输入、焦点、弹层及资源。显式 grants，不依赖缺省 capabilities；关闭 WebView feature。运行时不使用 Node/npm，TSX 由锁定的 Rust bundler 构建。

候选成功不等于已经交付第三方扩展 SDK、JSON 插件或进程级崩溃隔离。主线保持无 NSH 的可运行回退。

## ADR 004：恢复与保存

决策：专用串行 SQLite worker，WAL + FULL。第一次 dirty 必须有自包含基线，后续增量日志与周期压缩；拒绝每 250ms 重写 64 MiB 全文的方案。UI 传不可变 Rope，队列有预算，版本断层通过完整快照恢复连续性。durable 只随成功提交推进。

压缩必须校验生命周期和版本，保留快照版本之后的增量；丢弃墓碑不能被迟到工作复活。恢复只读取草稿，不自动覆盖原路径。启动元数据查询不得读取所有草稿内容。

保存捕获版本，后台流式编码，同目录临时文件同步后原子替换，禁止先删原文件。恢复库故障不阻止显式抢救保存；磁盘发布与恢复确认分别报告。文件身份/mtime 只能发现部分外部修改，不是严格并发内容证明。

## ADR 005：大文件与多文件预算

决策：默认有界 read-at，分页只读，不将大文件塞入普通 Editor。全局页面缓存 64 MiB、全局索引预算 16 MiB、单次显示文本至多 64 KiB，长行显示连续片段，不整行 shaping。预算是所有打开文档共享，不是每标签一份。

普通文档另有全局内容准入预算（设计值 256 MiB）与至少容纳 100 个小型已修改标签的实体上限；这不是进程 RSS 上限。可回收未编辑且无撤销历史的非活动视图，不能驱逐未保存内容或静默清除撤销。超预算磁盘文件走分页；恢复草稿保留数据库内容并需要导出救援路径。准入与大粘贴限制不能阻断已接受文档的普通键入/撤销。具体实现与边界以运行验证为准。

字节导航先可用，行索引后台渐进；未知行号不伪装精确。每次读取/搜索绑定 source generation，发现截断/替换/不兼容变化使旧结果失效。mmap 不默认用于用户可变文件，避免外部截断导致 SIGBUS。后续以真实测量决定预读/块大小/索引策略。

## ADR 006：搜索与实验

决策：默认 UTF-8 区分大小写字面量、从左到右非重叠。跨块 carry 受全局 next-allowed offset 控制；`aaa` 在 `aaaaa` 只命中一次。空查询不扫描；长度最多 64 KiB；结果最多 10,000；达到上限标记 truncated/countExact=false。队列满时取消仍能生效。

实验同时测原始顺序读取、优化 memchr matcher 与替代算法、不同块大小、多文件工作集、取消。不能用稀疏零文件推导磁盘吞吐；不能省略搜索内容或关闭恢复换取漂亮数字。

## ADR 007：日常编辑功能与可发现性

决策：默认展示可折叠的打开文档/最近文件侧栏，加入命令面板及快速切换器；语言、编码、换行和缩进使用明确选项，而非循环切换。复用Kit 0.9.0原生输入、虚拟列表与弹出菜单，不引入WebView或NSH。列表只读取内存元数据，不因展示或过滤而hydrate标签、扫描目录、stat最近文件。

焦点是正确性约束：命令面板位于workspace内联层，不能把编辑动作直接挂在会先向查询输入框派发的`CommandItem::action`上；确认后关闭面板并将焦点归还文档，再执行动作。行编辑快捷键仅在`Input mode=editor`生效，不能在查找框输入时修改正文。`⌘⇧D`改为复制活动行，主题保留菜单/工具栏/命令面板入口。

元素上下文写作`Input mode=editor`，快捷键谓词必须写作`Input && mode == editor`；两种字符串语法不能混用。

自定义复制/删除/移动/注释操作统一经过workspace原子事务与恢复提交路径，处理CRLF、末行无换行和选区末端位于下一行开头；受4 MiB预算约束。固定上游没有公开完整多光标选区列表，因此这些命令明确作用于活动选区并收拢其他光标，不虚称多光标操作；原生缩进操作保持上游语义。JSON、纯文本及需块注释的语言不冒充支持行注释。

视图偏好与最多30条最近文件保存在独立、版本化、有界的`ui_shell.json`，文件读写上限256 KiB。后台加载合并启动期间已发生的用户修改；单写入者合并最新状态并在退出时确认完成。损坏配置保留副本并报告，不静默覆盖。主题、自动换行、空白字符与缩进宽度不改变文本dirty；仅即时更新活动编辑器，后台标签激活时再应用，避免重排所有文档。

## ADR 008：保存格式基线与仅元数据修改

决策：`DocMeta`分别保留当前编码/换行与已保存编码/换行基线，save intent携带捕获的格式。保存期间再改格式，完成旧保存不得把新选择标为已保存；恢复时不能只比较文本hash忽略BOM/EOL。

文件关联文档，以及已有内容或持久恢复点的草稿，实际格式改变（含切回原格式）推进一次宿主revision并持久化元数据，但不伪造文本修改、撤销或原生编辑事件。相同选项为NoOp；切回已保存格式清除格式dirty，不影响真正的文本dirty。尚未输入的空白草稿只更新会话布局，不制造dirty或恢复内容头。旧恢复记录缺少格式基线时保守保持dirty，直到保存或重载。

元数据还有独立的入队顺序约束：草稿提交可批处理，而会话布局可立即执行，不能用worker实际执行先后决定哪份语言/格式元数据更新。两条路径按接纳时的单调序号排序，SQLite提交成功后才推进已应用水位；旧快照仍可提交其文本版本，但不得覆盖较新的元数据。保存关联基线另按捕获保存版本合并。

本轮设计及UI/格式恢复实现经`design-review`复审；运行验收与独立存储对抗复查的证据边界另记测试报告。

## 审查来源与证据边界

本轮由项目 `design-review` 评审并修订上述契约。其最初误将 macOS 描述为虚拟机，已纠正；最初建议 per-key Rope equality 与 checkpoint-only 的潜在性能风险也已明确排除。评审结论只许可实施；构建、数据可靠性及性能结论见实际验证记录。
